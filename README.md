# Java Maryland Container Tracking

Container tracking and delivery coordination built with Next.js, React and TypeScript.

## Setup

Requires Node.js 20.9 or later and npm.

```powershell
npm ci
Copy-Item .env.example .env.local
```

Set `API_BASE_URL` in `.env.local` to the backend URL, including `/api`. Use an existing workspace account to sign in. Restart the application after changing the backend URL.

## Development

```powershell
npm run dev
```

Open http://localhost:3000.

## Production

```powershell
npm run build
npm start
```

Set `API_BASE_URL` in your hosting provider's server environment, including `/api`. Use a stable HTTPS backend URL for production; temporary `trycloudflare.com` URLs depend on a running local tunnel. The frontend requires a Node.js server for its API proxy and cannot be deployed as a static export.

## Checks

```powershell
npm run typecheck
npm test
```

## Project structure

- `app/`: pages and backend API proxy.
- `components/`: shared layout and interface components.
- `lib/`: API client, response mapping, state, date and tracking utilities.
- `public/`: static assets.
- `scripts/`: unit-test runner.

## Backend integration

Container records, summary metrics, shipment timelines, delivery updates and workspace settings use the configured backend. Authentication uses an HttpOnly session cookie; credentials and access tokens are not embedded in source code.

Standard Excel downloads are generated by the backend. Search and combined-transit exports are assembled from all matching API records in the browser.

Workspace accounts are managed by an administrator. Help articles are bundled with the application; support requests are handled by the workspace administrator.
